# Acceptance of products / services

AP s.4 is the test gate between delivery and payment. Hardware and software must pass the tests below before acceptance. Related services: inspect the work. Concept page: [[acceptance-tests]]. Payment only after the Acceptance Certificate: [[04-payment]]. Default timetable: [[02-acquisition-brief]].

## General (AP s.4.1)

B/Ds are responsible for acceptance of hardware and software procured under GITP. All hardware and software must pass:

1. Installation and Function Tests; and
2. Reliability Tests.

For related services, inspect the work to ensure it is satisfactorily completed. On satisfactory completion of tests/inspection, issue an **Acceptance Certificate** (sample Annex 9) to the Contractor.

## Installation and Function Tests (AP s.4.2)

The Contractor activates and accesses all hardware units and runs all software packages installed to ensure the batch specified in the Proposal is properly installed. The B/D’s **authorised user** observes and records results. If all acquired items are present and function tests succeed, the **user and the Contractor** sign the Installation/Function Tests Report (sample Annex 10).

## Reliability Tests (AP s.4.3)

After successful Installation and Function Tests, carry out Reliability Tests for **four (4) consecutive weeks** to determine whether the batch achieves the minimum performance level (Reliability Levels) in **Schedule 8 of the Contract Schedules**.

Record problems in a **Reliability Tests – Fault Record** (sample Annex 11) and pass it to the Contractor for remedial action **immediately**. If a batch fails to conform fully to the Reliability Levels, re-conduct the tests for **another four (4) weeks**.

If repeat tests show the System or any part is not in conformity with the specifications, Reliability Levels, and Performance Criteria **after six (6) weeks from the date the System was first submitted** to Reliability Tests, the B/D may act under **Clause 11.1 and/or Clause 11.2** of the [[conditions-of-contract]] — several alternatives, including the right to refrain from issuing order for any hardware and software under the Contract. B/Ds decide which alternative fits the case.

On success, complete the **Reliability Tests Summary Report** (sample Annex 12) and issue an Acceptance Certificate (Annex 9).

**Silence rule.** The Contractor would assume the hardware/software has passed Reliability Tests and is accepted if B/Ds **do not report any problems** during the reliability test period.

## Certificate of Product Patching (AP s.4.4)

Contractors have been advised to deliver ordered hardware/software with the **latest patches**. At acceptance, the Contractor submits a Certificate of Product Patching certifying that action, listing all patches applied and any applicable patches **not** applied, with reasons (sample Annex 13).

Note 6 (booklet): a patch is a modification to a computer program to remove a deficiency (fix a bug); object code inserted into an executable; also called a fix, update, or upgrade.

## Regulated electrical equipment (AP s.4.5)

If the purchase involves regulated electrical equipment (e.g. a monitor), the Contractor must provide the appropriate **recycle label** issued by the Environmental Protection Department for each unit upon delivery, and a receipt with **prescribed wording about the recycling levies** on or before the invoice.
