# CSB ITMU Security Team

The CSB ITMU Security Team handles IT security issues in CSB. It gives **centralised coordination and technical support** to the three CSB divisions, and technical advice to the [[dso|DSO]] and Division [[isirt|ISIRTs]] so they can decide on information security incidents (DITSP s.5.2). Part II’s **[A]** tag includes CSB ITMU among IT Staff. See [[compare-roles]] and [[01-management]].

## Policy, advice, and change

The team helps the [[ditso|Division DITSO]] write the Departmental IT Security Policy and Guidelines so both business and technology concerns are addressed, and helps [[information-system-owner|Information System Owners]] write system-specific policy (DITSP s.14.1.1). With the Division DITSO it reviews DITSP regularly and oversees two-year [[security-risk-assessment|SRA and audit]] follow-up (ss.14.1.3, 20.2).

Ongoing advisory: the team should keep pace with technologies and market trends so new threats and their resolutions are identified in time (s.14.1.4). On urgent issues such as virus outbreaks and intruder attacks, it collaborates with the Division DITSO to propose safeguards and seeks DSO endorsement for prompt action.

A [[security-risk-assessment]] before a major change (upgrade, computer-room relocation) is treated as less complex than the two-year cycle and should be done by the ITMU Security Team or the system’s IT staff (s.20.1). Project owners should seek ITMU advice on the latest outsourcing security requirements (s.14.2). Information System Owners should seek ITMU advice before laying out security requirements in application design (s.18).

## Incidents, malware, and SAM

On a serious or public-aware incident the Division IRM notifies CSB ITMU (with DSO and [[giro]]) within 60 minutes; ITMU advises the DSO if needed and notifies IRMs of the other divisions (DITSP s.21.4). For serious incidents escalated to the DSO, the team **leads the aftermath** and coordinates the three divisions; it also prepares Post-Incident Analysis with the IT support team (s.21.5). See [[incident-handling]].

Virus-alert messages should be disseminated centrally through the Division DITSO or this team, which can check alerts with AV suppliers or hoax lists (s.19.4). Public-domain software and freeware, if needed, should be installed only with approval from the Division DITSO **or** CSB ITMU Security Team (s.19.5.1). File-sharing proposals go to ITMU for advice first.

DITSP records CSB’s use of Microsoft Systems Management Server (SMS) to automate software deployment, inventory scanning, and metering for [[copyright-compliance|software asset management]] and [[patch-management]] (s.17.9).
